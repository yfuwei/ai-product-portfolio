01｜Running Example / User Task

How does one promotion campaign become a launch-ready content package?

A marketing team starts with a rough promotion idea, not a complete brief. The product turns it into an executable Brief, creative direction, channel versions, review tasks, and feedback rules.

Raw Input

One-line campaign request

“Summer promotion: we need content for the website, social posts, and paid feeds.”

This kind of input usually lacks audience, value-priority, channel specs, brand limits, and review requirements.

Structured Fields

Fields to complete and confirm

  • Campaign goal
  • Target audience
  • Value-priority
  • Channel specs
  • Brand voice
  • Legal / risk boundary
  • Language and market context
  • Review owner
Output Package

Launch-ready package

  • Campaign Brief
  • Creative Direction
  • Channel versions
  • Review Tasks
  • Launch-ready assets
  • Feedback and asset rules

AI role: AI is not replacing designers or operators. It turns vague campaign requests into inputs, versions, reviews, and feedback that can be confirmed and reused.

02｜Business Problem / Process Breaks

Faster generation can mean faster rework.

When the Brief is vague, direction unconfirmed, versions scattered, and review delayed, AI scales the confusion.

  1. Campaign Request
  2. Brief
    Vague Brief

    Missing audience, value-priority, channel goals, and review requirements.

  3. Creative Direction
    Unconfirmed Direction

    The team finds the message, visual style, or brand voice is wrong only after assets are drafted.

  4. Channel Versions
    Scattered Versions

    Website, social, article, and paid-feed versions are edited separately, with scattered status.

  5. Review
    Late Review

    Brand voice, banned terms, and compliance issues surface late in the process.

  6. Launch Review
    No Feedback Loop

    Performance data stays in reports instead of returning to Briefs, templates, asset libraries, and rules.

If these breaks are not productized, faster AI generation only brings rework, review friction, and version chaos faster.

04｜Core Product Objects

Define the objects before generating outputs.

Only when Briefs, versions, reviews, and feedback become product objects can AI outputs move through the workflow and be reused.

Object Layers

Input Objects
  • CampaignGoal, timeline, channel scope, owner
  • Campaign BriefAudience, value props, limits, review needs
  • Creative DirectionMessage angle, visual direction, key message
Production Objects
  • Channel RulesSize, CTA, copy length, publishing rules
  • Candidate AssetsCopy options, images, banners, social posts
  • Review TasksBrand, legal, and channel-rule review
  • Confirmation RecordsWho approved what, and what changed
Feedback Objects
  • Performance FeedbackClicks, conversion, engagement, channel feedback
  • Reusable Assets / Brand RulesTemplates, bad cases, assets, generation strategy

State Flow

  1. DraftingCampaign request enters the system
  2. StructuredBrief, direction, and channel rules are completed
  3. Pending ReviewCandidate assets enter brand, legal, and business review
  4. ConfirmedConfirmation records bind owners and change requests
  5. LaunchedAssets enter channel publishing
  6. Fed BackPerformance feedback becomes assets and rules
Fed-back learnings improve the Campaign Brief, creative direction, and channel rules.

An AI output only becomes part of production when it is tied to an object, a state, an owner, and a feedback path.

06｜Product Evolution Path

Generation alone does not build production capability.

From one-off image output to templates, versions, review, and feedback loops, the evolution is not about faster generation. It is about leaving reusable learning after each production cycle.

V1

Generation Support

Capability: Generate a first draft from a single brief or prompt.

Value: Reduces the cost of getting from zero to first draft.

Boundary: Outputs are hard to reuse; review and feedback remain outside the system.

V2

Template-based Production

Capability: Standardize Brief fields, prompt templates, style rules, and channel specs.

Value: Makes inputs more stable and outputs more controllable.

Boundary: Still focuses on before and during generation; collaboration and state management are limited.

V3

Multi-channel Workflow

Capability: Bring website, social, article, and paid-feed versions into one state flow.

Value: Connect generated outputs to review, approval, publishing, and version management.

Boundary: Still needs performance feedback to become reusable learning.

V4

Feedback-driven Asset System

Capability: Performance feedback, bad cases, reusable assets, and brand rules return to the next campaign.

Value: Builds a reviewable, accumulative, continuously improving content asset system.

Boundary: Does not replace final brand, legal, or business responsibility.

The point is not for AI to generate more content, but for every generation to be reviewed, reused, fed back, and used to improve the next campaign.

07｜Validation Method / Project Boundary

Output must enter the workflow to count as validated.

This project does not package real launch results. It validates whether the production mechanism from Briefs, versions, review, and feedback loops can hold together.

What is validated

Validation Objects

  • Whether a vague request can become an executable Brief
  • Whether creative direction can be confirmed before production
  • Whether channel versions can enter state management
  • Whether review tasks can bind brand, legal, channel rules, and owners
  • Whether feedback can return to templates, bad cases, assets, and brand rules
How it is validated

Validation Method

  • Run the sample Campaign through creation, Brief, direction, versions, review, and recap
  • Use low-fi prototypes to test whether key screens support decisions
  • Use product objects to test whether each screen binds state and ownership
  • Use boundary lists to identify where human review is mandatory
  • Use recap paths to test whether feedback becomes reusable rules
What is not claimed

Project Boundary

  • No claim of real commercial launch results
  • No claim that AI replaces brand, legal, or business owners
  • No claim that “good-looking images” are the only validation standard
  • No claim that prompt tuning equals full product capability
  • No coverage of real ad budget systems, publishing systems, or channel backends

The value of this project is not proving that AI can generate content, but proving that generated content can enter a reviewable, confirmable, and feedback-driven production mechanism.
