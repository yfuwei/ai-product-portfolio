A02｜Service Context Linking

A03｜Multi-Agent Execution & Replanning

找回任务之后，AI 开始组织工作。

B01｜业务场景与产品定义

让 AI 接续一笔反复被催办的退款，而不是重新回答一次。

以电商退货退款的重复催办为切片，把历史承诺恢复为可执行任务，跨仓库与退款业务域持续推进。

SIMULATION · 模拟业务场景｜产品方案设计与前端演示，不代表真实企业调研、生产运行或已验证业务结果。

1.1 业务故事

周五 · 第三次催问 · CONV-003

“上次不是说帮我去仓库查吗？现在怎么还是没消息？”

  • 周三 CONV-002 曾承诺安排仓库核查。
  • 同一笔 RET-001 物流已投递，仓库尚未确认有效入库。
  • 周五未找到有效、可追踪的关联核查任务。

客服已经答应处理，但缺少可追踪的任务接续。

当前业务状态：物流已投递仓库未确认退款尚未发起

1.2 用户与任务

一线客服
找回历史服务事项，查看可追踪执行进展，审核待发送的客户阶段性回复。
Agent 任务跟进人员
查看任务进展、Waiting、异常和当前执行事项，定位需要人工跟进的业务问题。
客服运营
比较跨 Case 的相似业务卡点，核查候选问题及证据缺口。

客户是服务对象：提出退款咨询，预期获得后续处理进展；当前没有独立实现客户侧前台。回复仅为待发送 Mock，未实际送达。

Service Orchestrator、Warehouse Agent、Refund Agent 属于系统执行角色，不是企业使用者。

1.5 MVP 边界

Flow A｜单 Case 服务任务续办（核心 MVP）

围绕 CASE-001，恢复并持续推进同一笔 RET-001 的退款服务目标。

  • 跨会话恢复目标，主编排组织专业查询。
  • WH-201 Waiting；事件恢复后核实有效记录。
  • 更新计划，续办退款异常任务，回传客服待发送草稿。

Flow B｜跨 Case VOC（客户之声）问题发现（独立辅助能力）

比较多条独立模拟 Case 的服务记录，识别重复业务卡点并排除不同处理阶段。

  • 形成候选问题，不把关联当成共同根因。
  • CI-001 · Need Evidence，仍需补证。
  • TASK-001 尚未创建，仅为条件性改进任务预览。

单笔服务记录可沉淀为跨 Case 的分析输入；两套工作流独立运行。

Flow A 产生的记录可成为 Flow B 的数据来源之一；Flow B 使用多个独立 Case，不是 Flow A 的自动下一步，也不阻塞单笔退款处理。

B02｜Multi-Agent Workflow 设计

从历史任务恢复，到跨 Agent 执行与动态重规划。

把周五的追问转为可继续执行的服务任务，说明谁来做、工具返回什么，以及新结果如何改变下一步。

方案设计 + 模拟业务数据｜下文 Trace 为预期执行过程，业务工具与 Agent Runtime 均未真实接入。

2.1 跨会话业务关联与任务恢复

周五的追问，凭什么关联到周三对 RET-001 的核查承诺？

  1. CONV-003当前追问
  2. CONV-002历史核查承诺
  3. RET-001同一笔退货
  4. CASE-001恢复服务目标

为什么关联到 RET-001？

  • 属于同一客户范围，指向同一笔 RET-001。
  • CONV-002 存在明确的仓库核查承诺。
  • 当前未确认入库、缺少核查记录，与这项待续办事项相符。

什么情况需要停止自动关联？

  • 相似催问属于另一笔退货。
  • 无法证明历史承诺属于 RET-001。
  • 业务对象关系冲突。
  • 关联依据不足 → 保留待确认，不执行另一笔退货的任务。

AI 理解“上次帮我查”的指代，提出候选；业务关系定位记录，可信知识依据解释为何仍需核查入库。工具在客户访问范围内核对承诺与事实；相似文本不证明关联，LLM 不补全缺失事实。

2.4 异步等待、事件恢复与继续执行

WH-201 等待仓库核实结果；挂起期间保留任务，不持续调用 LLM。业务事件用于唤起复核，不直接把核查变成完成。

匹配与去重

事件不必携带 WH-201 ID。用 RET-001 等业务对象定位等待任务，核验同一退货与当前任务；去重后再恢复。找不到唯一关联时不自动推进。

核实与回传

有效入库记录确认后，完成 WH-201 并向主编排返回结果；记录仍未有效确认时继续 Waiting 或待核实，不解除仓库阻断。

拟将业务关联键映射到持久化执行线程；应用层负责事件接入、任务定位与去重，框架暂停 / 恢复不能替代业务核验。事件 ID 等为拟议字段，非真实系统日志；映射与恢复正确性仍待验证。

Service Orchestrator · 主编排消费新的有效业务结果，改变下一步行动；事件到达不等于阻断解除。

独立模拟分支 · 发现疑似既有退款任务

Refund Agent 在另一售后记录中找到疑似任务时，先核对三项业务依据，不与上方 RF-301 新建主场景混成同一次历史：

  • 是否属于同一 RET-001。
  • 是否属于同一未完成退款事项。
  • 任务是否仍有效，有何处理进展。

确认有效后返回 Service Orchestrator，接续原任务并跟踪，不重复创建 RF-301；未确认关联不能直接复用。

计划更新使用新的有效业务事实，不把条件分支描述为完全自主的 LLM 规划。

LangGraph｜拟采用

让应用掌握等待任务的状态、恢复入口与剩余计划分支，承接本场景的具体控制需求。

Dify｜可视化备选

快速验证标准 Agent、工具查询与较固定工作流；不同分支和等待机制需结合实现评估，不断言其无法完成对应能力。

尚未接入真实 LangGraph Runtime 或企业 API，尚未完成事件恢复测试；持久化配置、业务映射、去重与各分支待最小 Mock 执行验证。当前仅为产品方案与模拟状态，没有 Workflow 执行测试结果。

5.4 不只统计回答次数，而是衡量服务任务是否接续

四项口径均待测量，暂无实测数值。先固定纳入规则、真值与观察窗口；分母为零时不计算比例。

M01 · 待测量历史任务关联判断正确率

AI 找回的是正确的未完成事项吗？不相关的历史任务有没有被排除？

具有明确业务对象关联真值、且实际触发历史任务关联判断的模拟或服务样本。

分子正确恢复目标任务，或正确排除不相关历史任务的样本数分母具有人工确认关联真值的历史任务判断样本总数

观察错误退货关联、错误历史承诺、错误续办目标，以及本应排除却被错误恢复的任务。

T01 对应正确恢复，T07 对应正确排除；分子、分母统一按判断样本计数，每个样本只计一次。未恢复不等于正确排除；证据不足、尚无真值的样本单列为待核实，不进入统计。

M02 · 待测量任务有效接续率

恢复目标后，是否产生可追踪的后续动作？

仅纳入符合续办条件、且预先约定的观察窗口已结束的恢复任务。

分子正确进入有效后续执行或接续既有任务的数量分母符合续办条件且观察窗口已结束的恢复任务数量

有效 Waiting 且尚未到观察终点的任务单列，不直接算失败。仅有客服回复，没有可追踪动作，不算接续。

M03 · 待测量事件恢复与重规划正确率

新结果是否正确改变后续执行？

仅纳入需要事件恢复或计划判断、且有可核验预期分支的样本。

分子实际恢复与分支行为符合预期的样本数分母该类可核验样本总数

核对事件关联、业务记录复核、Waiting 解除及剩余任务分派。不是每个事件都更新计划；条件未满足时保持原分支也可符合预期。

M04 · 待测量重复任务创建率

已有有效任务时，是否仍错误新建？

仅纳入已有可核实的有效关联任务、且触发创建或接续判断的场景。

分子仍错误新建重复任务的场景数分母已有有效关联任务且触发该判断的场景总数

越低越好。无有效既有任务的主场景不进入此分母；疑似关联需先核实，不能仅凭相似文本合并。

业务结果观察｜客户是否还需要反复催问？

短期产品验证 · 服务进展可追踪性

客服是否能看到当前处理任务、最新执行阶段和下一步待办，并向客户准确反馈？

  • 关联同一笔退货的历史服务任务。
  • 有可追踪的仓库核查或退款后续任务。
  • 区分 Waiting、任务已启动与实际退款完成。
  • 向客户解释当前进展和后续动作。

可优先使用结构化 Mock 场景验证；目前没有真实运行结果。

长期业务效果 · 同一事项重复催问率

服务任务持续接续后，客户围绕同一未完成事项的重复咨询是否减少？

分子在约定观察期内，就同一未完成服务事项再次发起催问的退货业务对象数量分母进入该观察期、且存在未完成服务事项的可比较退货业务对象总数

按同一退货对象、同一未完成事项关联，排除不同退货或问题的误合并。观察期依据实际退款处理周期确定；后续与改造前或可比较样本对照，考虑退款类型、处理难度及观察窗口差异。当前仅定义口径，尚无重复催问减少的结论。
