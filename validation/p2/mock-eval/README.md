# 退货退款与 VOC｜规则级 Mock 验证

这是一套纯 Python 标准库的确定性产品规则验证。它执行合成业务输入，不调用 LLM、Agent、LangGraph、企业 API 或真实业务事件。

Round 1 输入、预期与历史输出原样保留。当前规则在 Round 2 的组合冲突复核中实际发现并修正 H02 / H04；首次 2 PASS / 2 FAIL，复测 4 PASS，T01–T14 回归 14 PASS。两项简化策略仍 FAIL。完整审计、首次记录、修正及新指标见 [round2/README.md](round2/README.md)。

复现当前 T 集时使用新输出名，避免覆盖历史记录：

```sh
python3 validation/p2/mock-eval/run_eval.py --output round2/t-reproduce-fixed.json --run-id reproduce-fixed
```

下文记载的是 Round 1 历史范围和结果；历史命令不应直接覆盖已有文件。

## Round 1 历史复现记录

在作品集仓库根目录运行（Python 3.10+）：

```sh
python3 validation/p2/mock-eval/run_eval.py --output results-initial.json --run-id initial
python3 validation/p2/mock-eval/run_eval.py --run-id recheck
```

实际执行环境为 Python 3.14.2。脚本保存所有预期、实际输出、字段差异和禁止动作。仅目标规则 FAIL 或关键错误导致非零退出；两项刻意简化的对照策略失败单独保留，不冒充目标规则失败。

## 数据与证据

- `fixtures.json`：T01–T10 与 T11–T14 的结构化输入、冲突、BC 编号和预先指定的指标集合。
- `expected.json`：根据本轮产品要求手工预设的输出与禁止动作，先于脚本执行固定；真值仍需人工审查。
- `test-set-manifest.json`：执行前冻结的输入与预期 SHA-256；标签变更会阻止运行。
- `rules.py`：只消费输入，不读取预期答案。返回规则决策和内存模拟状态。
- `run_eval.py`：独立比对预期与实际，保存失败，计算指标；不根据输出来改标签。
- `results-initial.json`：本轮第一次实际运行结果。
- `results.json`：相同输入、预期与代码的复测输出。
- `recheck.json`：两次运行的哈希和观察一致性核对，未发生规则变更或目标规则修复。

输入与预期文件先写入、冻结，然后才创建规则及执行器。预期来自产品任务说明，不是模型能力评测的专家标注数据集。

## 三类结果

1. **目标规则真实失败**：本轮 0 / 14，首次运行与复测均未出现；没有生产事故、旧 Agent 版本或修复历史。
2. **负向样本正确拦截**：T04 / T07 / T08 / T10 / T11 / T12 / T13 / T14 共 8 条，判定 PASS。
3. **简化策略对照失败**：真实运行两条控制策略。T11 把事件当成核实事实，产生提前完成 WH、Plan v2、创建 RF 的错误；T14 把相同文本当成共同根因，误合并 Case 并确认 CI / 创建 TASK。这是人为限定策略的实验错误，不是声称已发生的 Agent 故障。

“修正规则”指对照策略加入产品约束后的目标规则对比，目标规则预先已定义。复测是相同代码再运行，不伪称本轮修复了真实 Agent。

指标集合在执行前固定于每个输入样本的 `metric_groups`。首次与复测结果一致。

| 指标 | 实际值 | 分母及边界 |

| Waiting 恢复判断正确率 | 5 / 5 | T03 / T04 / T05 / T11 / T13；验证决策与全部预设字段，不验证真实恢复机制 |
| 候选关联与排除正确率 | 8 / 8 | T09 与 T14 各四个 Case 判断；相同业务事实以不同文本配置重复验证，不是八笔独立真实 Case |

关键错误计数覆盖上述危险提前动作、重复建单、错误业务对象关联、证据不足误确认与误创建任务。目标规则本轮关键错误为 0；所有目标断言也必须 PASS 才满足小样本最低门槛。不能据此宣称生产可靠。

## 未验证范围

- 自然语言理解与意图识别：`intent`、业务阶段、关联 ID 已在合成输入中给定；T09/T14 的阶段判断不是模型推理。
- 真并行、工具可用性、实时业务结果：T02 仅检查查询意图；其余工具返回为手工输入。
- 状态持久化、跨进程恢复、消息队列、真实去重：T03 的上下文仅为输入/输出对象；T13 仅同一进程内事件 ID 列表，不验证进程重启或 exactly-once。
- 过期/乱序事件、同一事件 ID 内容冲突、多个有效退款任务、失败重试、授权、真实退款与客户消息发送。
- 补证齐全后的根因确认、运营审核、正式改进任务创建与改善效果。当前 VOC 规则只覆盖候选筛查和缺证拦截，不具备根因推断能力。
- LangGraph Runtime、企业仓储 / 退款 API、真实客户重复催问率、退款时长、VOC 运营指标。

下一轮优先接入可持续的任务交接与存储、跨进程事件恢复及更完整证据分支，再考虑真实 Agent / 企业系统验证。
